# Issue 8 validation

## Implementation

The shipped host uses Pi Durable, Pi-ai and Chord pinned at **1.1.0**. Marketplace policy is session-scoped, independent of the conversation transcript. SQLite is opened with WAL and `synchronous=FULL`; a separate SQLite database holds the process-lifetime owner lock. Forks and child conversations are disabled. There is no old-runtime adapter or state importer.

Breaking package changes: `actors`, `self`, `turn`, `PersonaActor`, `loadModel` and `setModelFactory` are removed. Hosts use `openMarketplaceAgent` from `/agent` and `startListener` from `/listener`, and close streams before stores. `/model` exposes `createAgentModels`. `/policy` and `/storage` expose the policy and storage boundaries. Tool enum values and CLI command names are unchanged; UUID inputs are normalized so casing cannot change an action's identity. Write/money tools must now provide an action key at compile time.

## Folder ownership clarification

The user clarified that one `agents/<id>/` folder is the complete agent: its behaviour, credentials, wallet material and permanent history move together while stopped. Defaults now place provider settings in that folder's private `.env`, the encrypted wallet at `.taskfast/wallet.json`, its user-created unlock file at `.taskfast/wallet-password`, and Pi state at `.pi-state/<cli-env>/state.sqlite`. Setup never reads repository-level settings, and each model collection uses its own settings without modifying process-wide environment. CLI children run from the agent directory so relative wallet paths survive relocation; their environment remains PATH, HOME and TASKFAST_CONFIG only.

Policy v2 verifies the stable agent UUID through one read-only `me` before initializing/resuming work, then binds UUID plus environment instead of a filesystem location. A real Pi/SQLite regression physically moves a stopped simulated agent folder and verifies retained notes, spending and permanent duplicate blocking with a fresh tool call. Different UUIDs, environments and invalid/unreadable identities are refused before model work. A synthetic policy v1 store remains untouched and is rejected without migration/reset. **The earlier development posting evidence used policy v1. Its existing store/config/wallet were preserved, not relocated, imported or reopened under v2; it is not evidence of live v2 signing or recovery.**

Other regression slices first failed for shared setup settings, host-key fallback, arbitrary CLI cwd and external host state paths, then passed at the setup, model, CLI and host boundaries. Concurrent native Ollama-compatible HTTP requests carry distinct folder-scoped keys/endpoints even with conflicting host settings. Required exported credentials are saved into the selected agent folder; provider credential-file paths are stored relative and must stay within that folder. Native Bedrock ambient/profile credentials are refused in folder-scoped mode because its pinned adapter can consult machine-level sources; its bearer-token mode remains supported. The generated provider guide records that restriction. A shared explicit host unlock fallback is not part of a portable archive; folder-local unlock files take precedence.

Independent Standards and Spec reviews found a prior-location ledger bypass, lexical credential containment and native-provider ambient setting fallback. Regression tests reproduced each before the fix. Startup now refuses prior shared-default store/companion files before opening any agent; arbitrary external old locations cannot be discovered automatically and must not be replaced with blank state. Credential/settings paths reject symlink components. Generated provider metadata names native environment dependencies, and dispatch refuses undeclared host values before invoking the adapter. A native Azure regression reproduced a request carrying a synthetic folder key to a host-selected localhost endpoint, then verified that the fix blocks it with zero requests. Stream-option handling and path checks are shared helpers. A follow-up SDK audit found direct ambient organization/project and custom headers, proxy settings, and AWS configuration inputs that bypass scoped env; these are refused, including machine-level AWS configuration files. Cache retention is explicit rather than inherited. A separate organization-header regression reproduced the missing refusal, then passed; copying an SDK-only value into the folder does not weaken that guard. Setup also refuses linked settings before reading/writing their targets. Independent follow-up found linked agent roots/state directories plus SDK-only Vertex endpoints and OpenAI custom headers. All four regressions first failed, then passed after root/state containment and additional unconditional SDK guards; agent specs are checked before reading through linked roots.

Archives contain credentials and can include the unlock file, so they must be encrypted. Move only stopped complete folders, preserve every state/companion file, and never run original and restored copies together or restore older state to unblock writes. A local ownership lock does not coordinate separate copies/machines. No user credentials, password, keystore or existing agent/state files were inspected, copied or moved during this continuation. No network marketplace write or production request was made.

Final folder-continuation checks: frozen installation/build, typecheck and **214 tests across 14 files** passed, including the unchanged kit scan. Both independent review axes identified defects that were fixed with observed red/green regressions; narrow follow-up reviewers verified the final correction hunks with no further findings. HEAD, NUL inventories, staged/unstaged/net diffs and untracked-content hash were rechecked for drift.
